0.2.0 UI·조작 편의성 검토

현재 Unity 프로젝트와 이전 실행본을 기준으로, 메뉴를 여닫는 동선과 전투 정보를 읽는 과정을 점검했습니다. 플레이 범위는 여섯 인물·마을·수련·Act 1의 두 보스입니다. 전체 캠페인이나 완성 스프라이트를 추가한 버전은 아닙니다.

메뉴 입력은 게임이 한 곳에서 처리합니다. 방향키·Tab으로 포커스를 옮기고 Enter로 확인하며, 선택된 버튼에는 테두리가 나타납니다. 기본 UI 시스템과 이야기 진행 코드가 동시에 확인 입력을 처리하지 않도록 했습니다. 터치는 버튼의 포인터 이벤트와 실제 Raycast 경로를 함께 검사합니다.

Tab과 양쪽 Shift+Tab은 화면 끝에서 처음·마지막 버튼으로 순환합니다. H는 마을·전투·정비 메뉴에서 도움말을 열고, 도움말 안에서는 원래 화면으로 돌아갑니다. 큰 버튼 모드에서는 이동 패드 크기에 맞춰 마을 NPC 줄의 중앙도 옮깁니다. 아이폰 비율에서 첫 NPC 버튼이 패드에 조금 가려지던 재현 조건을 포함해 다시 검사했습니다.

일시정지에서 도움말을 열었다가 돌아와도 전투를 자동으로 재개하지 않습니다. ‘전투 계속’을 선택한 뒤 현재 타격이 이어집니다. 실제 전투 귀환에서는 현재 보스의 체력 초기화를 안내하고 취소할 수 있으며, 진행 손실이 없는 수련은 바로 종료합니다. 장면을 건너뛰거나 보고 버튼을 중복 요청해도 기존 체크포인트와 1회 보상 규칙은 유지합니다.

스킬 배치는 A·S를 아래, D·F를 위에 두고 R 각성기를 옆에 둡니다. 버튼 이름에서 가운데 점으로 연결된 각성기 이름은 의미 단위로 줄을 나눕니다. 크기를 바꾸면 이동 패드와 기술 버튼의 위치도 함께 조절하고, 전투 가로 투영 간격을 조절해 시작 위치의 보스가 조작부에 가려지지 않게 합니다. 점프 그림자와 앞뒤 순서도 전장 깊이 위치에 맞춥니다.

확인 범위는 Windows의 1560×720 화면과 iPhone 15 Pro 비율의 2556×1179 화면 모사입니다. 기본·큰 조작 크기, 최대 저장 대화 글자 크기, 메뉴 겹침과 화면 밖 이탈, 스킬 30개, 중첩 메뉴, 저장 복원과 기존 스토리 회귀를 포함합니다. 빌드 GUID와 게임 어셈블리 해시를 확인해 해당 빌드의 검사 결과만 배포 파일에 묶습니다.

검사 수와 범위는 `QA/verification.json`, 장면은 같은 폴더의 `20-settings-large.png`, `21-controls.png`, `21-skill-0-4.png`, `22-large-training.png`, `23-mana-status.png` 등에서 확인할 수 있습니다. 검사 수에는 각 화면의 글자·버튼 경계 검사도 포함됩니다. 모든 숫자가 독립된 플레이 시나리오를 뜻하지 않습니다.

포인터 이벤트와 메뉴 포커스를 PC에서 모사한 검사입니다. 아이폰 OS의 실제 손가락 조작·시스템 제스처·진동·Metal 성능·발열은 아직 확인하지 않았습니다. IPA 제작은 계속 보류한 상태입니다.
